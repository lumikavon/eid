# Epic 3 Context: 查找并使用可追溯、已授权的证据

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

让作者从企业知识与本地附件中查找、核对真实来源片段，将当前有权且有效的证据绑定到章节和可核查的 Claim；保留版本、定位与冲突，避免检索分数、过期材料或无依据的引用被误当作事实证明。

## Stories

- Story 3.1: 安全上传并检查解析后的附件
- Story 3.2: 安全检索企业知识与本地附件
- Story 3.3: 保留来源权威、时效与冲突
- Story 3.4: 建立章节 Evidence Pack 并检查支撑
- Story 3.5: 绑定可核查 Claim 并在指定选区插入引用

## Requirements & Constraints

- 附件需验证身份、类型、大小、散列与内容，隔离解析 PDF/DOCX/XLSX/图片及 OCR；保留文件、页、章节、chunk 的定位和部分成功/失败状态。恶意输入须拒绝或隔离；重复任务不得生成重复的规范解析记录。原件的工作区、所有者、密级及保留策略不能被索引改变。
- 检索必须在权限、范围、密级、上下文及版本有效性约束下进行前后过滤，模型使用、来源查看与引用时重验当前授权；撤权、外部 ACL 不可证、适配器故障时拒绝相关使用，不能暴露标题、摘录、计数或敏感日志。精确标识符须有关键词/元数据路径，不能仅依赖向量召回；企业链不强制重建索引。
- 九档来源权威与安全密级分别管理；优先适用且有效的高权威来源，但竞争断言与具体版本须进入可检查的冲突记录。LLM 一般知识不算正式 Evidence；失效或无权材料不得以历史快照重新授权。
- Evidence 保存来源文档及版本、章节/chunk、页或位置、原文、检索/重排分数、时效与策略溯源。章节 Pack 对检索结果去重、标注冲突和不足原因，记录查询与版本；支持不足、预算耗尽、来源撤权时不能宣称关键事实已有支撑。
- Claim 覆盖数字、百分比、性能、容量、时间、日期、型号、标准、法规、能力、验收阈值、客户/项目名及版本等可核查类型，保留条件、值/单位、位置及未知类型；区分支持、部分支持、冲突、不支持和未知，关系区分 supports/conflicts/contextual。关键 Claim 缺少有效依据须可定位、待确认或待复核；置信度、链接数不等于事实成立。检索 P95<3 秒、典型 Pack P95<8 秒及权限错误检索为零是后续冻结工作负载下的验收目标，不是已通过结果。

## Technical Decisions

- 企业知识经能力声明的内部 Gateway 适配现有服务；没有可证明的预过滤 ACL 或有效来源定位时，不把结果作为正式 Evidence。本地授权附件独立使用 PostgreSQL pgvector、FTS/jieba、BGE-M3 与 reranker 的版本化检索链；无法使用的链应明示不可用而非伪报全量结果。
- API 掌握当前授权、引用写入及文档版本提交；Worker 仅以受限委派处理解析、索引、检索及任务结果，不扩大原用户权限。危险解析/OCR 工具在无网络、无 DB/MQ 凭据、非 root、只读根目录且资源/时间/临时文件受限的隔离环境中执行；对象定位符本身不授予下载权。
- 章节/Claim 查询规划生成 3–10 个子查询；短事务外完成检索，提交 Pack 前重验权限。Pack 固定来源版本/chunk、查询及检索/重排版本、策略散列、缺口与冲突；快照只作溯源。Claim↔Evidence 关系及 AST 稳定块/选区书签绑定到文档版本；引用操作校验当前书签、基础版本、引用原文与来源授权，冲突时保留正文并要求重新选择。引用变化使受影响的 Claim/Review 待复核。
- 跨 Web/API/Worker 的知识、任务、文件和 AST 契约保持版本化、幂等与当前权限检查；任务进度、部分失败及重试须持久且可辨。敏感摘录与完整正文不放入消息或普通日志。

## UX & Interaction Patterns

- 保持现有编辑器、P-05 证据栏及 Review 来源卡片的视觉和入口；P-10 原型只有导航与占位，知识搜索/来源详情、X-10 查看器和 X-11 冲突管理属于按 UX 契约补充的新内容，不虚构原型像素基线。来源页提供范围/版本/分类过滤、企业/附件/Golden 分类、真实片段及版本/定位/权威/有效期/冲突细节；冲突两侧都可检查，但无权侧不泄露摘录。
- 按当前选中的章节、Claim 或问题显示 Pack 和对应来源；切换选择时不得保留前一个来源详情。编辑器“插入引用”先固定真实选区书签，选来源并确认后才写入准确位置；失效选区要求重选，不插首段。明确展示解析中、部分完成、Pack 构建、无支撑、过期、禁止访问与链路不可用；撤权清除受控摘录，错误提示不可泄露受保护的元数据。Toast 不是唯一持久状态。

## Cross-Story Dependencies

- Epic 1 提供当前身份/授权和持久任务；Epic 2 的项目上下文、已确认大纲、版本化 AST 与冲突处理是附件、章节 Pack、精准引用的前提。本 Epic 顺序为附件解析→双链检索→权威/冲突治理→章节 Pack→Claim/引用；后续生成、Review 与发布使用固定 Pack 及当前授权重验，不可把本 Epic 的支持状态自动当作发布批准。
- 当前仅允许软件开发、静态检查与编译等活动；故事中本地运行、真实企业/模型检索效果及数值性能验收均未执行，须保留为 `not-run`，不能以替身或源码检查声称真实集成已通过。
