# Epic 2 Context: 受控文档创建与编辑

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

作者在当前权限内选择模板、文种及知识范围，创建具有独立标识和固定模板版本的文档；随后以领域 AST 保存编辑历史、处理并发冲突，确认项目事实与必需大纲。模板管理员可以发布新版本而不改写既有文档。本 Epic 交付软件实现；运行验收另记 `not-run`。

## Stories

- Story 2.1：选择模板并创建目标文档。
- Story 2.2：编辑与编辑器解耦的领域 AST。
- Story 2.3：无损保存和处理并发版本。
- Story 2.4：治理可复用模板版本。
- Story 2.5：组装并确认项目上下文。
- Story 2.6：生成前确认完整大纲。

## Requirements & Constraints

- 当前只执行软件开发、源码/契约/配置静态检查、编译和离线构建，以及独立代码审查与修复；不启动或使用服务、数据库、浏览器、测试套件或现场环境进行功能验证。原运行案例逐项保留为 `not-run`，静态检查不能替代其结果。
- 所有读取与写入须满足当前 RBAC 操作权限、ABAC 对象范围和密级，并在提交事务中重新核对；客户端传入的 workspace、project、scope 或角色不能成为授权依据。失权后不得返回旧的幂等成功正文。
- 五种模板范围为企业、部门、产品线、项目、个人草稿；搜索、分类、文种与范围筛选取交集。模板选择、预览、详情和创建都绑定实际所选版本及其自身结构。过期、无权或并发废弃的模板禁止新建使用。
- 文种目录覆盖三期规划；目录存在不代表后续各文种的专属工作流已经实现。开发样例须标明，缺正式模板/字体/政策时不能表示正式可用。
- 创建文档须保存修剪后的非空名称、文种、允许的知识范围、模板版本、独立文档 ID 和初始 AST。取消不写入；重复提交通过受当前授权约束的幂等记录避免重复创建。同一键不同内容返回冲突。
- 正文权威是不可变 DocumentVersion 的领域 AST，不是浏览器 DOM 或 Tiptap 私有 JSON。版本与模板固定绑定；Section、Block、Claim、Citation 保留稳定 ID。未知未来节点只读保留；非法更新保留上一个有效版本；Published 版本不可直接编辑。
- 保存以 `base_version_id` 与 `document_revision` 做乐观并发检查。冲突保留 base/local/latest 供人工选择；保存状态只有服务端确认后才显示成功。敏感正文和令牌不进浏览器持久存储。
- 项目事实、单位、来源、术语、约束和缺项须显式记录与人工确认；上下文与大纲分别固定版本。缺必需章节、旧版本、无权限或未人工确认时，不能进入后续生成资格。

## Technical Decisions

- 仅有 `edw-web`、`edw-api`、`edw-worker` 三个业务工程。API 是人工创建、编辑、模板发布、上下文/大纲确认的权威入口；Worker 不直接移动文档 head，也不能决定人工审批、权限或正式发布。共享 Python domain/application/persistence 是库，不新增监听服务。
- API 使用 `/api/v1`、snake_case、不可猜测 ID、UTC 时间、结构化错误和 `Idempotency-Key`。创建成功返回 201；`TEMPLATE_DEPRECATED` 与版本冲突为 409；可纠正输入为 422；有权看见但不能操作为 403，隐藏对象存在时为 404。
- PostgreSQL 与单一 Alembic 链保存 Document、DocumentVersion、TemplateVersion、上下文、大纲、审计和幂等事实；关键写入在短事务内核对权限、模板状态和当前版本。模板已被引用的版本不可物理删除。
- 初始 AST 采用 `schema_version: "1.0"` 和 `document.metadata/sections/claims/citations/review_state` 结构。编辑器仅通过双向 adapter 转换；不能吞掉未知扩展、表格结构、资源引用或来源绑定。
- 新增依赖与契约须锁定并检查；不得以本轮静态/编译结果声称真实 PostgreSQL、浏览器、企业系统或容量验收通过。

## UX & Interaction Patterns

- 保留原型首页、创建弹窗、模板中心和编辑器现有布局、控件顺序、样式与窄屏横向滚动；原始 `docs/prototype/index.html` 不修改。新增页面遵循 UX 契约，不冒称已有像素基线。
- 首页五个快捷创建入口与模板卡片“使用”均打开创建弹窗，保留发起入口选择的文种与模板。弹窗必须显示名称、文种、知识范围；取消不写入，失败保留输入，成功导航到新文档自身 ID/AST。Toast 只能补充持久的错误和任务状态。
- 模板中心保留原有范围页签、分类 chips、卡片及右侧详情；补全产品线/项目范围和文种选择。切换选中卡片时清理旧的可操作详情，预览和“使用”始终指向同一真实模板版本。
- 编辑器树、标题、正文、工具栏和保存状态来自选中文档的 AST 与已确认版本；上下文与大纲有独立可见的确认/缺项状态。对话框有名称、键盘焦点和返回焦点；背景点击不隐式取消创建。

## Cross-Story Dependencies

- 2.1 依赖已完成的工作区发现和当前授权接口，提供模板目录与初始文档供后续使用。
- 2.2 依赖 2.1 的 Document/TemplateVersion 与初始 AST；2.3 再在其上提供 CAS、历史与人工合并。
- 2.4 依赖 2.1 的模板版本引用及既有任务观察能力；2.5 依赖 2.2 的文档结构；2.6 依赖 2.5 的上下文确认和 2.4 的模板规则。
