# 当前软件开发与验证规则

生效日期：2026-09-21。依据：用户最新指令及项目 AGENTS.md 的开发与验证约束。

## 适用范围与优先级

适用于 `_bmad-output` 的 PRD、架构、UX、全部 Epic/Story、实施规格与后续派生计划。本规则覆盖旧文档中要求当前启动服务、运行测试或现场验收的执行安排；功能需求、安全约束、验收目标、Story ID 与责任归属保留。历史记录按原日期保留，不代表本轮执行或授权。

本次只调整规划，不启动开发流程、不修改业务代码或 Story 完成状态。

## 当前允许的工作

- 软件层面的开发、修复、测试代码和验证方案编写。
- 源码与差异审查、静态分析、语法/类型/lint 检查，以及不连接实际服务的配置和契约静态检查。
- 编译、打包和构建验证。运行前先检查实际脚本、依赖脚本和构建钩子；若包含服务启动、测试、迁移、fixture、部署或实际环境访问，拆出纯检查/编译步骤，不能直接运行整套命令。
- 每个 Story 保留检查 → 优化 → 验证闭环；检查和编译失败须修复后复查，不跳过或伪造结果。

## 当前不执行的活动

- 不启动实际运行环境进行功能实测，也不使用已启动的实际环境进行功能实测；该限制同时适用于本机、远端、容器、开发/测试与生产等环境。
- 不启动 Web/API/Worker、基础设施或模型服务；不启动隧道、部署候选、执行迁移、seed/fixture 或数据库读写验证来准备实测。
- 不运行功能测试、集成测试、E2E、浏览器交互/截图验收、真实模型效果评测、企业联调、UAT、负载/性能测试、故障注入、升级/回滚或恢复演练。当前验证限于代码检查和编译，测试代码可以编写、审查和编译，不执行测试套件。
- 不进行任何实物、硬件或现场环境的运行验证。

原有远端部署与隔离数据库授权保留其历史边界，不能覆盖本规则恢复运行。环境已就绪、旧测试曾通过、自动化工具建议或前序软件工作完成，均不构成恢复实测的指令。
