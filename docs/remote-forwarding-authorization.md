## 请求的最小变更

只针对 `seadee` 账号、来自现有跳板 `172.16.10.3`、连接 `172.27.0.38:22` 的会话，允许 SSH 本地转发；目的地限定为以下远端 IPv4 loopback 端口：

| 服务 | 允许的远端目的地 |
|---|---|
| Web / OIDC | `127.0.0.1:18080` |
| PostgreSQL | `127.0.0.1:55432` |
| Keycloak 管理检查 | `127.0.0.1:58080` |
| RabbitMQ AMQP | `127.0.0.1:55672` |
| RabbitMQ 管理检查 | `127.0.0.1:55673` |
| Redis | `127.0.0.1:56379` |
| S3 | `127.0.0.1:58333` |

拟生效的限定规则如下。实际落点须在授权后读取现有 Include/Match 顺序确定，不能盲目追加并假定生效：

```text
Match User seadee Address 172.16.10.3 LocalAddress 172.27.0.38 LocalPort 22
    AllowTcpForwarding local
    PermitOpen 127.0.0.1:18080 127.0.0.1:55432 127.0.0.1:58080 127.0.0.1:55672 127.0.0.1:55673 127.0.0.1:56379 127.0.0.1:58333
Match all
```

保持其他账号、来源、远端转发和既有 GatewayPorts 策略；不开放服务公网监听，不批准任意目的地或全局转发。SSH 服务端规则限制可达目的地；本工作站隧道仍由项目守卫核验只绑定 `127.0.0.1` 及指定进程全部监听。

1. 保留现有管理会话；重新核对目标主机、连接来源及 sshd 实际启动配置路径。
2. 在读取有效 Include/Match 结构后备份将修改的精确文件，生成仅上述范围的候选差异并保存。
3. 执行 sshd 配置语法检查，分别核验目标条件、其他来源及其他账号的有效策略，确认仅目标范围变化。失败时不加载。
4. 采用服务支持的配置重载方式，保留既有管理会话；新建连接验证管理访问和七个限定目的地，以及非白名单目的地、远端转发被拒绝。
5. 按修复并独立审查后的隧道入口重建项目转发，核验 argv、全部监听、目标及真实客户端连接；失败保留证据并恢复该次精确配置变更。
6. 隧道通过后，才按现有 EID 专属资源授权继续远端配置部署、RabbitMQ 数据保留验证、初始化、迁移和三工程验收。任何 Story 仍须各自测试、独立审查、状态校验和提交。
