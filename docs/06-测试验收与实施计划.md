# 测试验收与实施计划

**文档编号**：EDW-TECH-SPEC-006  
**版本**：V1.1

---

## 1. 测试目标

验证系统不仅“可以调用 LLM”，而且满足：

- 文档工程正确；
- 知识检索可靠；
- Evidence 可追溯；
- AI 关键事实受控；
- 权限不泄漏；
- Reviewer 可发现问题；
- 输出文档可正式使用；
- 整体性能满足企业日常使用。

## 3. 功能验收

### 3.1 技术方案

至少验证：

- 项目资料被正确检索；
- 公司技术标准优先于普通历史资料；
- 关键参数有 Evidence；
- 模板必选章节存在；
- 生成架构章节可追溯；
- 全文参数一致。

### 3.2 PRD

- Feature 结构；
- NFR；
- 异常流程；
- 权限；
- 验收标准；
- Requirement ID。

### 3.3 测试方案

至少验证：

- 从需求生成测试项；
- Requirement ↔ Test 双向追踪；

## 4. RAG 评测

### 4.1 Golden Query

每个文档域建立 50~200 条代表性查询。

例如：

- “当前云桌面项目并发规模是多少？”
- “公司质量制度要求哪些设计评审？”
- “技术方案的高可用章节应该引用哪些规范？”

### 4.2 指标

建议初始门槛：

| 指标 | 一期目标 |
|---|---:|
| Recall@10 | ≥ 0.90（Golden Set） |
| 权限错误召回 | 0 |
| 失效版本优先于现行版本 | 0 |
| 当前项目正式资料 Top3 命中 | ≥ 95%（适用查询） |

## 5. AI 生成评测

### 5.1 Unsupported Critical Claim Rate

定义：

```text
无有效 Evidence 的关键事实数量
/
关键事实总数
```

建议一期目标：

- 通过 Review 后 < 2%；
- 正式发布关键 Claim = 0 个严重 Unsupported。

### 5.2 Citation Precision

随机抽样引用，验证引用来源是否真正支持正文。

建议目标 ≥ 95%。

### 5.3 Human Edit Distance

统计：

- AI 生成内容最终保留率；
- 人工修改比例；
- 严重事实修改率。

不要求“AI 原文保留越多越好”，而是用于持续优化。

---

## 6. Reviewer 评测

构造故障注入集：

- 数字冲突；
- 客户名残留；
- 旧版本引用；
- 无依据性能参数；
- 模糊技术要求；
- 缺章节；
- 需求漏响应；
- 引用无权限；
- 标准编号错误。

测试：

- Precision；
- Recall；
- Severity 是否合理。

严重类 Reviewer 以 Recall 优先。

## 7. 安全测试

### 必测用例

1. 用户 A 搜索用户 B 私有项目知识；
2. 通过自然语言诱导 AI 输出无权限文档；
3. 知识库文档中植入 Prompt Injection；
4. L2/L3 内容尝试路由到外部模型；
5. Prompt 中含 Access Key；
6. 导出已撤销权限文档；
7. 旧链接访问 Evidence；
8. 审计服务异常时尝试正式发布。

## 10. 基础设施与恢复验收

至少覆盖：

1. Docker Compose 开发环境一键启动、数据库迁移和示例数据；
2. Helm 在测试 Kubernetes 集群完成滚动部署/回滚；
3. NGINX SSE 长连接在代理、重启和客户端重连场景下可恢复；
4. RabbitMQ quorum queue 单节点故障/消费者重启后任务不丢且无不可控重复副作用；
5. Celery Worker 在任务执行中退出后，PostgreSQL 状态机可识别并重试/补偿；
6. CloudNativePG（或等价企业 PostgreSQL HA）故障切换；
7. Barman Cloud 备份恢复演练，验证 RPO/RTO；
8. SeaweedFS/企业 S3 的对象版本、生命周期、临时文件清理和权限；
9. Redis 清空/重启不得导致文档、审批、任务永久状态丢失；
10. OpenTelemetry → Prometheus/Loki/Tempo 的 trace/metric/log 关联可用。

## 12. 一期验收门槛

必须同时满足：

1. 4 类一期文档均可完整创建；
2. Template + Evidence + Section Generation 全链路可用；
3. 关键事实支持来源追溯；
4. 文档版本、Diff、审校、审批可用；
5. 严重权限泄漏 = 0；

7. DOCX 可直接用于内部正式评审；
8. 核心性能达到 NFR；
9. 审计链完整；
10. 故障恢复验证通过。

## 15. 上线后持续优化

每月分析：

- 文档生成成功率；
- AI 内容保留率；
- Reviewer Issue 分布；
- Evidence 空缺；
- RAG 低命中查询；
- 用户手工修改类型；
- 文档编写耗时；
- 审批耗时；
- 模型成本。

优化顺序：

```text
Knowledge
→ Template
→ Retrieval
→ Prompt
→ Reviewer
→ Model
```

不应遇到问题就直接升级更大的模型。
